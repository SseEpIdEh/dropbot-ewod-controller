# EWOD Vision V4.11 — Electrode-aware ITO experiment

**Status: Experimental, read-only. No actuation. Not a validated droplet detector.**

## Purpose

V4.10 first identifies changed image regions anywhere inside the yellow rectangular ROI and only later assigns an electrode/channel. After repeatedly lifting/replacing ITO glass, electrode-border reflections can produce false detections. Shrinking the ROI helps, but eventually excludes important electrodes, including large bottom channel 33.

V4.11 is an *independent* extension that uses existing saved 8-point electrode calibration (`ewodHomography`, `ewodProjectElectrode`), the real electrode polygons in the blue SVG and their `data-channels` values **before** thresholding. It searches electrode polygons plus a small neighborhood, not all of a rectangle. **It does not know which changes are true droplets** and may still be fooled by glass edges crossing the electrode surfaces.

## What is included

- Analysis at **1920 × 1080** or **960 × 540**, native max if camera currently delivers Full HD.
- **Every calibrated electrode** as a search region, including reservoirs and bottom electrode **ch33**. Yellow ROI clipping is optional and OFF by default; ROI no longer needs to exclude useful electrodes.
- The SVG *actual path geometry* and DropBot `data-channels` assignments, not hardcoded channel numbers. On a changed calibration, the active preview stops.
- Up to **four genuine EMPTY-chip-with-ITO reference images**, held in page memory, allowing a multi-empty reference comparison. This is a conservative engineering experiment, **not the same as optical subtraction of the ITO glass**. May hide some real droplet pixels; compare one-reference and multi-reference modes.
- Small integer image translations (±3 analysis pixels) estimated from electrode texture, a per-region connected-components check, electrode overlap channel votes, and a minimum of two sequential frames for on-screen markers.
- Four panel diagnostics, read-only video overlay and downloaded PNG+JSON diagnostics.
- NO DropBot calls; no writes to legacy `window.ewodVisionState`, the V4.7/V4.8/V4.9/V4.10 reference states, or the saved magenta/ROI calibration.

## Installation

1. Stop other previews and keep DropBot Realtime OFF. Stop the Python server if you prefer, but it does not need to be running to install.
2. Download and unzip `ewod-v411.zip` into `~/Downloads`.
3. In the existing `dropbot38` Terminal:

```bash
cd ~/Downloads
unzip -o ewod-v411.zip
cd ewod-v411
bash install_v411.sh
```

The script verifies V4.10 is installed and V4.11 has not already been appended. It creates a timestamped backup alongside `~/ewod-ui/static/js/ui-controls.js` and **appends** the additive extension. It does not replace any prior code. It is designed for the full `ui-controls.js` where V4.10 has already been installed. If your working file differs from the known controller, review differences before using it.

4. Start Flask from `~/ewod-ui`, not the ZIP folder, if necessary:

```bash
cd ~/ewod-ui
conda activate dropbot38
python app.py
```

5. Open `http://127.0.0.1:5001` and do Chrome **Command + Shift + R**. Expand **Experimental V4.11 — electrode-aware ITO diagnosis** after V4.10.

## Controlled test procedure

**A. First establish your reference (absolutely EMPTY chip).**

1. Calibrate/restore magenta, verify electrode fit. Freeze camera and lighting; keep zoom 1.0×.
2. With NO DROPLETS and ITO in its first marked mechanical position, click **Add EMPTY ITO reference**. Up to four reference captures are permitted, but each must be made with an absolutely EMPTY chip.
3. Optionally lift and replace the STILL EMPTY ITO glass in a second physical placement; capture another **Add EMPTY ITO reference**. Repeat for up to four representative glass placements. Do not move the camera or PCB; if the camera/chip moves, recalibrate and clear V4.11 refs.
4. Run preview while EMPTY, observing the count of **stable candidates** across 30 seconds. Save diagnostics. Compare with V4.10 using the same empty conditions.

**B. Add droplets after all EMPTY references are captured.**

5. With high voltage disabled, open ITO as needed, pipette a droplet directly onto a known transport electrode; close the glass and restore spacing/pressure.
6. Start V4.11 Preview with one droplet; log actual placement, volume, count and screenshot; record whether predicted primary channel agrees. Repeat for two or three droplets. No automatic actuation.
7. If a reference was captured with a droplet, **Clear V4.11 references** and repeat with a genuinely empty chip. Never recapture a reference to hide a real droplet.

**Recommended comparison:** V4.10 vs V4.11, with single vs multiple EMPTY ITO references, and ROI clipped vs full electrode network. Use exactly the same physically counted droplets. Capture the count and position of **false positive / missed / duplicate regions** and mean frame latency. Keep test sequences independent from the samples used for tuning.

## Limitations and known risks

- This algorithm is NOT ML fine-tuning. It is a **classical electrode-aware candidate detector**, intended to produce better data for later U-Net/YOLO-seg training.
- A glass boundary *crossing an electrode* may still be falsely reported. A droplet near that boundary might be rejected. Multi-empty per-pixel minimum is a heuristic, not a robust physical reflection model.
- Registration adjusts only small **global** integer shifts. ITO glass can shift independently of the PCB, affecting shadows and refraction locally. This cannot be corrected by registration alone.
- The algorithm is specific to one known PCB layout/calibration; calibrated paths and channel metadata must be valid. It needs an exact physical wet/dry ground truth to establish correctness.
- The two-frame persistence is a tentative stability gate; motion blur, subtle droplets, and pressure changes can still cause false decisions. Frame time may be significantly higher in the browser with 1920×1080 and four empty references.
- These tentative regions should NEVER drive electrode voltage or the autonomous state machine. Manual visualization and independent capacitance checks remain separate.

## Research reading informing the approach

1. Guo et al., *Topology-based coordination control for multi-droplet tasks in autonomous digital microfluidics*, Lab on a Chip (2026), DOI `10.1039/D6LC00147E`: learned semantic segmentation and droplet–electrode topology, not a glass repositioning correction.
2. *An artificial intelligence-assisted digital microfluidic system for multistate droplet control*, Microsystems & Nanoengineering (2024), DOI `10.1038/s41378-024-00775-5`: U-Net-style segmentation of labeled droplet states; data and feedback control.
3. Deng et al., *A Hybrid Closed-Loop Droplet Detection for Digital Microfluidics*, IEEE Sensors Journal (2025), DOI `10.1109/JSEN.2025.3541135`: YOLOv5 and electrical impedance, different sensing architecture.
4. Li et al., *Toward Intelligent Microfluidics: An LLM-Based Droplets Controlling Framework*, IEEE RA-L (2026), DOI `10.1109/LRA.2026.3674635`: language/topology planning with camera feedback; not segmentation of glass-reposition artifacts.
5. Song et al., *Darkfield illumination enhancing artificial-intelligence-assisted digital microfluidics for on-site pathogen detection*, Analytica Chimica Acta (2026), DOI `10.1016/j.aca.2025.344831`: optical-contrast improvement on a transparent ITO chip; our opaque PCB needs different lighting geometry.

## Research-grade evaluation suggestions

Record a `ground_truth.csv` with session ID, actual physical droplet count, initial electrode(s), volume, ITO position ID, ROI configuration, illumination, V4.11 version, and whether the droplet moved. Create trials with empty chip / empty glass repositioned / one / two / three droplets, with duplicates and misses annotated. Evaluate per physical trial, not just correlated video frames. Never equate a channel score with measured droplet volume.
